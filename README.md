# Employee Registry

Консольное приложение для учёта сотрудников на Java.

Это проект, который я развиваю **версиями**: от чистого ООП до приложения на Spring с PostgreSQL. Каждая версия добавляет новую технологию и улучшает код предыдущей. История хранится в тегах (`v1`, `v2`, …) и Pull Request'ах.

![Java](https://img.shields.io/badge/Java-21-orange)
![Maven](https://img.shields.io/badge/build-Maven-blue)
![Status](https://img.shields.io/badge/version-v1-green)

## Возможности

- Добавление сотрудника (имя, должность, зарплата)
- Просмотр списка всех сотрудников
- Повышение зарплаты на заданный процент
- Удаление сотрудника по ID
- Поиск сотрудников по должности (без учёта регистра)
- Валидация вводимых данных и понятные сообщения об ошибках

## Технологии

- Java 21
- Maven
- Хранение данных: в памяти (`HashMap`), на старте работы приложения база пуста

## Запуск

Требования: JDK 21+ и Git.

## Архитектура

Приложение разделено на слои, каждый отвечает за одну задачу:

```
src/main/java/com/<username>/employeeregistry/
├── Main.java                  # консольный интерфейс: ввод, вывод, меню
├── model/
│   └── Employee.java          # сущность
├── repository/
│   └── EmployeeRepository.java  # хранение данных (Map в памяти)
├── service/
│   └── EmployeeService.java   # бизнес-логика и валидация
├── exception/
│   └── ItemNotFoundException.java
└── util/
    └── Validator.java         # проверки входных данных
```

Поток данных: `Main` → `EmployeeService` → `EmployeeRepository`.
`Main` ничего не знает о хранении, `Repository` ничего не знает о правилах бизнеса.

## Известные ограничения (v1)

- Данные теряются при завершении программы
- Нет автоматических тестов
- Логика ввода и вывода пока частично смешана с сервисом (будет исправлено в v2)

## Процесс разработки

- Каждая версия разрабатывается в отдельной ветке `feature/vN-<тема>`
- Слияние в `main` только через Pull Request
- Коммиты небольшие, в формате `feat:`, `refactor:`, `test:`, `docs:`, `chore:`
- Каждая версия отмечается тегом
